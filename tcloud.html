Установка ноды TCloud на NAS UGREEN

UGOS Pro · Docker Compose · Identity · Setup · проверка запуска

❗ Выполняйте установку с компьютера, подключённого к той же сети, что и NAS. Значения в примерах нужно заменить на свои.

💻 Что подготовить на компьютере

КомпьютерКомпьютер, с которого можно открыть панель управления роутером и веб-интерфейс NAS.
Доступ к роутеруАдрес панели управления, логин и пароль администратора роутера. Не путайте их с названием и паролем Wi-Fi. Обычно данные для входа указаны на наклейке роутера.
Фиксированный внешний IPНужен фиксированный (статический) внешний IPv4. Его можно подключить у интернет-провайдера или организовать другим способом через арендованный VPS.
Доступ к UGOS ProАдрес NAS, логин и пароль администратора UGOS Pro.
ТерминалТерминал на компьютере с Windows, macOS или Linux для подключения к NAS по SSH.

⚡ Краткая последовательность

  1. Создать Storage Pool и Volume на диске для ноды.
  2. Закрепить постоянный локальный IP за NAS.
  3. Убедиться, что есть внешний статический IPv4.
  4. Пробросить порты 14002 и 28967 на NAS.
  5. Включить SSH в UGOS Pro и подключиться к NAS.
  6. Создать каталоги TCloud.
  7. Создать docker-compose.yml.
  8. Создать Identity.
  9. Выполнить первичную настройку Setup.
  10. Запустить контейнер.
  11. Проверить контейнер, процессы, порты и Dashboard.

📌 ШАГ 1. Подготовить диск

  1. Откройте в UGOS Pro раздел управления хранилищем.
  2. Создайте на нужном диске отдельный Storage Pool.
  3. Создайте Volume и дождитесь состояния Normal.
  4. Не выделяйте под ноду весь объём: оставьте запас для системы и служебных файлов.
Пример результатаДиск 18 TB → Storage Pool 1 → режим Basic → Volume 1 → состояние Normal → для ноды выделено 16000GB.

📌 ШАГ 2. Закрепить локальный IP

  1. Откройте список клиентов DHCP на роутере.
  2. Найдите UGREEN NAS по имени или MAC-адресу.
  3. Создайте привязку, чтобы NAS всегда получал один и тот же адрес.
  4. После сохранения проверьте, что веб-интерфейс NAS открывается по этому IP.
Пример результатаUGREEN NAS → MAC 84:47:09:12:34:56 → постоянный IP 192.168.1.120.

📌 ШАГ 3. Проверить внешний IPv4

Откройте сайт 2IP с компьютера, подключённого к вашему роутеру. Сайт сразу покажет текущий внешний IP-адрес.

Открыть 2IP.ru
  1. Запишите IP-адрес, который показал сайт.
  2. Сравните его с фиксированным внешним IPv4, который сообщил интернет-провайдер или который настроен через VPS.
  3. Если вы не знаете выданный адрес, запишите показание 2IP, выключите роутер из розетки, снова включите его и после восстановления интернета повторите проверку.
  4. Если адрес не изменился, вероятнее всего используется ваш фиксированный внешний IP. Если остаются сомнения — уточните адрес у провайдера.
Пример результатаДо перезагрузки: 203.0.113.25
После перезагрузки: 203.0.113.25
Адрес совпадает с выданным провайдером.

📌 ШАГ 4. Пробросить порты

Названия разделов отличаются в зависимости от производителя и модели роутера. Войдите в панель управления роутером и найдите раздел с одним из названий:

Возможные названия разделаПроброс портов, Переадресация портов, Port Forwarding, Virtual Server, NAT или Перенаправление портов.
  1. Если раздел найти не получается, введите в поиске модель роутера и фразу «проброс портов».
  2. В качестве внутреннего IP во всех правилах укажите закреплённый адрес UGREEN NAS.
  3. Для порта 14002 создайте правило TCP.
  4. Для порта 28967 разрешите TCP и UDP. Если роутер не позволяет выбрать оба протокола сразу, создайте два отдельных правила.
  5. Сохраните и примените настройки роутера.
Dashboard14002 / TCP → 192.168.1.120:14002
Трафик ноды28967 / TCP+UDP → 192.168.1.120:28967
Не открывайте SSH-порт 22 в интернет. Он нужен только внутри вашей локальной сети или через защищённый VPN.
Пример результатаПравило 1: TCP 14002 → 192.168.1.120. Правило 2: TCP/UDP 28967 → 192.168.1.120.

📌 ШАГ 5. Включить SSH

  1. В UGOS Pro откройте Панель управления → Терминал.
  2. Включите SSH.
  3. Включите постоянную доступность SSH: выберите вариант Всегда включено или отключите автоматическое выключение — название зависит от версии UGOS Pro.
  4. Оставьте порт 22 доступным только в локальной сети. Не пробрасывайте его в интернет.
  5. На компьютере откройте Terminal, PowerShell или Windows Terminal и подключитесь к NAS.

Подготовьте команду подключения

Готовая команда подключения
ssh ivan@192.168.1.120

Введите пароль пользователя NAS. После подключения получите права администратора:

Переход в режим администратора
sudo -i

Снова введите пароль пользователя NAS.

Пример результата
ivan@UGREEN-NAS:~$ sudo -i
Password:
root@UGREEN-NAS:~#

📌 ШАГ 7. Создать Docker Compose

Сначала подготовьте адрес кошелька, e-mail, фиксированный внешний IP и объём, который хотите выделить ноде. Заполните поля ниже — страница сама создаст готовую команду.

Введите данные своей ноды

После нажатия кнопки вставьте скопированную команду в SSH-терминал и нажмите Enter. Она сама создаст docker-compose.yml с вашими данными и сразу проверит его.

Команда, которая будет скопирована
cd /volume1/docker/triangles && cat > docker-compose.yml <<'TCLOUD_COMPOSE'
services:
  node:
    image: registry.gitlab.com/softdds/tcloud:latest
    restart: unless-stopped
    ports:
      - "14002:14002/tcp"
      - "28967:28967/tcp"
      - "28967:28967/udp"
    environment:
      WALLET: "ВВЕДИТЕ_КОШЕЛЁК"
      EMAIL: "ВВЕДИТЕ_EMAIL"
      ADDRESS: "ВВЕДИТЕ_ВНЕШНИЙ_IP:28967"
      STORAGE: "ВВЕДИТЕ_ОБЪЁМ_GB"
    volumes:
      - /volume1/docker/triangles/config:/app/config
      - /volume1/docker/triangles/identity:/app/identity
TCLOUD_COMPOSE
docker compose config
Пример результата
name: triangles
services:
  node:
    image: registry.gitlab.com/softdds/tcloud:latest
    environment:
      ADDRESS: 203.0.113.25:28967
      EMAIL: node@example.com
      STORAGE: 16000GB
    ports:
      - 14002:14002/tcp
      - 28967:28967/tcp
      - 28967:28967/udp
✅ Если команда docker compose config завершилась без ошибки и показывает ваши значения, файл создан правильно.
↑ В начало

📌 ШАГ 8. Создать Identity

Identity — уникальные ключи ноды. Их нельзя терять или использовать одновременно на двух устройствах.

Создание Identity
docker run --rm -it \
  --mount type=bind,source=/volume1/docker/triangles/identity,destination=/app/identity \
  registry.gitlab.com/softdds/tcloud:latest \
  identity create storagenode
Проверка файлов Identity
ls -la /volume1/docker/triangles/identity/storagenode
Пример результата
ca.cert
ca.key
identity.cert
identity.key
✅ В папке identity/storagenode должны находиться файлы сертификатов и ключей.
Сделайте резервную копию папки identity и храните её отдельно от NAS.
↑ В начало

📌 ШАГ 9. Выполнить Setup

Команда создаст начальную конфигурацию в папке config.

Первичная настройка
docker run --rm -e SETUP="true" \
  --mount type=bind,source=/volume1/docker/triangles/identity,destination=/app/identity \
  --mount type=bind,source=/volume1/docker/triangles/config,destination=/app/config \
  registry.gitlab.com/softdds/tcloud:latest
Проверка конфигурации
ls -la /volume1/docker/triangles/config
grep -nE 'operator.email|operator.wallet:|contact.external-address|server.address' \
  /volume1/docker/triangles/config/config.yaml
Пример результата
config.yaml
operator.email: "node@example.com"
operator.wallet: "0x1234567890abcdef1234567890abcdef1234ABCD"
contact.external-address: "203.0.113.25:28967"
server.address: ":28967"
✅ В папке config появился config.yaml, а в нём указаны ваши e-mail, кошелёк и внешний адрес.

📌 ШАГ 11. Проверить работу

Свежие логи
cd /volume1/docker/triangles
docker compose logs --tail 100
Что должно быть в логахДопустимы обычные информационные сообщения запуска. Не должно быть повторяющихся сообщений FATAL, Invalid configuration, operator wallet address isn't specified или постоянных циклов перезапуска. Если вывод логов пустой, проверьте внутренние процессы следующей командой.
Внутренние процессы
docker exec triangles-node-1 supervisorctl status
Правильный результат
storagenode           RUNNING   pid 125, uptime 0:03:24
storagenode-updater   RUNNING   pid 126, uptime 0:03:24
Проверка опубликованных портов
docker port triangles-node-1
Правильный результат
14002/tcp -> 0.0.0.0:14002
28967/tcp -> 0.0.0.0:28967
28967/udp -> 0.0.0.0:28967

На компьютере в локальной сети откройте Dashboard по внутреннему IP NAS:

Адрес Dashboard
http://192.168.1.120:14002

http://localhost:14002 можно использовать только непосредственно на NAS или при специально настроенном SSH-туннеле. На обычном компьютере используйте внутренний IP NAS.

✅ Всё работает правильно, если контейнер имеет статус Up, оба внутренних процесса показывают RUNNING, опубликованы три порта и Dashboard открывается по внутреннему IP NAS.

🛠️ Если что-то не работает

Если установка не получилась или появились ошибки, сохраните вывод команд диагностики и обратитесь к своему вышестоящему спонсору.

Контейнер не запускается

Диагностика
cd /volume1/docker/triangles
docker compose config
docker ps -a
docker compose logs --tail 200

Ошибка про wallet или e-mail

Проверьте, что в compose и config.yaml записаны настоящие значения, а не пустые строки.

Dashboard работает, но нода offline

Сверьте внешний IPv4, значение ADDRESS, проброс 28967 TCP/UDP и правила брандмауэра. Внешний адрес должен быть актуальным.

После изменения compose

Безопасное пересоздание контейнера
cd /volume1/docker/triangles
docker compose down
docker compose pull
docker compose up -d
Не удаляйте папки config и identity. В них находятся данные и уникальная Identity ноды.
